## 赛场文字技巧

1. 比赛做题节奏
    - 开场先把所有题目快速扫一遍，不要一上来就在第一题坐太久。
    - 先做一眼能写的签到题和中低档题，优先保证有分入账。
    - 如果一道题想了 20 到 30 分钟还没有清晰做法，先暂时放掉，去拿别的题的分。
    - 比赛里最怕的不是不会，而是卡在一题上把后面的简单题也耽误了。

2. 读题技巧
    - 读题时先圈出：数据范围、是否多组数据、要求输出什么、下标从 0 还是 1 开始。
    - 特别注意 `n=1`、全相等、全负数、无解、答案可能很大这几类边界。
    - 看到“最多”“最少”“是否存在”“方案数”“字典序最小”时，要立刻意识到题型可能不同。
    - 样例不只是看答案，要看它在暗示什么性质。

3. 卡题时怎么自救
    - 先问自己：我卡的是思路、证明、实现，还是复杂度。
    - 把题目的目标换一种说法，很多题换个角度就清楚了。
    - 尝试手推 3 到 5 个小样例，找规律时不要一上来就盯着大数据。
    - 想不出来时，列出你已经确定正确的性质，再尝试拼做法。
    - 如果一个做法很复杂，优先怀疑自己是否想偏了。

4. 常见题型提醒
    - 数据范围很小：优先想暴力、搜索、状压、记忆化。
    - `n` 到 `2e5`、`1e6` 级别：优先想线性、`n log n`、前缀和、差分、双指针、单调栈、二分。
    - 涉及区间修改、区间查询：先判断是前缀和、差分、树状数组还是线段树。
    - 涉及“排序后更好处理”：优先考虑贪心、双指针、离线。
    - 涉及“不断合并/连通”：考虑并查集。
    - 涉及“方案数”“模意义”：留意 DP、组合数、快速幂、逆元。

5. 写代码前先确认四件事
    - 状态和变量分别表示什么。
    - 循环顺序是否会影响正确性。
    - 是否会越界。
    - 是否会爆 `int`，该不该开 `long long`。

6. 实现细节防挂分
    - 能开 `long long` 的地方尽量别省，尤其是乘法、前缀和、答案统计。
    - 数组大小宁可多开一点，不要卡边界。
    - 多组数据时，每组都要重新初始化。
    - 排序、自定义比较函数时，先确认比较规则是否满足严格弱序。
    - 二分一定想清楚：查的是第一个满足条件的位置，还是最后一个满足条件的位置。

7. 调试顺序
    - 先看输入有没有读错。
    - 再看数组下标和循环边界。
    - 再看转移、贪心条件、判定函数是否写反。
    - 最后看是否有未初始化、爆类型、特判漏写。
    - 调不出来时，自己造最小样例，比盯着大样例更有效。

8. 赛场上的心态技巧
    - 前 30 分钟不要慌，很多人这时候也只是刚进入状态。
    - 被卡住很正常，不代表你这场不行，只代表这题暂时不适合现在做。
    - 一道题过了以后，别沉浸太久，马上回到全场视角。
    - 如果连续 WA，暂停 2 分钟重新看题，通常比继续硬改更有效。

9. 提交前检查清单
    - 是否清空了上组数据影响。
    - 是否特判了最小值和无解情况。
    - 是否有 `mid = (l + r) / 2` 溢出的风险，可以写成 `l + (r - l) / 2`。
    - 是否有除 0、取模负数、访问空容器的问题。
    - 输出格式有没有多空格、多换行、少换行。

10. 临场思路习惯
    - 先想暴力，再根据数据范围优化，不要一上来就想特别复杂的做法。
    - 如果题目要求构造，优先从小样例出发，尝试找规律和不变量。
    - 如果题目要求最值，先想贪心、二分答案、DP。
    - 如果题目要求“是否存在”，先想判定条件能不能简化。
    - 如果你已经能写出一个正确但慢的做法，说明离正解通常不远了。

11. 容易忽略的边界
    - 空数组、单元素、全相同、严格递增、严格递减。
    - 有负数、有 0、答案可能为 0。
    - 图可能不连通，树可能要从任意点开始搜。
    - 字符串可能长度为 1，或者全部字符一样。

12. 明天比赛前可以再看一遍
    - 签到题不要写挂。
    - 中档题先拿到手。
    - 卡住及时换题。
    - 少写花哨写法，优先写自己最稳的写法。
    - 每过一题都把代码再扫一眼再交。
    - 相信自己平时训练积累的东西，比赛时先把会的都拿下。


13. 比赛里推荐的代码习惯
    - 统一决定数组是从 0 开始还是从 1 开始，不要混着写。
    - 能封装成 `solve()` 就封装，方便处理多组数据。
    - 变量名尽量别全写成 `a b c d`，至少关键变量要看得出含义。
    - 写完一段循环就顺手想一下边界，避免最后集中排错。

14. 容易写挂的输入问题
    - 题目是多组数据，但你只写了一组。
    - 题目给的是字符串矩阵，你却按字符一个个读，结果格式乱了。
    - 输入里有空格，用 `cin >> s` 读不完整，应该用 `getline`。
    - 没注意 1 下标和 0 下标，建图时直接错位。

15. 赛前最实用的一句话
    - 输入先读对，边界先想对，再谈算法。

4. 差分：  
    对于一个数列an，有q次修改，每次都把数列中li到ri的每个元素加上一个数值ki求出所有修改后的每个数字的值。   
    用数组delta[i]来维护第i个数字和前一个数字的差值，（可以默认第一个数字前面有一个0）然后当需要对[li,ri]区间的每一个数字+ki时，只需要修改delta[li]和delta[ri+1]即可。所有的修改完成后，在对delta数组求和，就可以得到数列的每个元素的数值。

8. **裴蜀定理**     
   对于任意两个不全为零的整数a,b 一定存在两个整数x,y 使得 ax+by=gcd(a,b)
   裴蜀定理：对于任意两个不全为零的整数a,b 一定存在两个整数x,y 使得 ax+by=(a,b)
  exgcd 是"扩展欧几里得算法"（Extended Euclidean Algorithm）的缩写。它是欧几里得算法的扩展版本。 
    基本原理
    普通的欧几里得算法只能求两个数的最大公约数(gcd)     
    扩展欧几里得算法不仅能求gcd，还能找到裴蜀定理中的系数 x和y     
    即对于任意两个整数a和b，求解方程：ax + by = gcd(a,b)    
    > 首先，考虑a和b的最大公约数d = gcd(a, b)。根据欧几里得算法，d可以通过反复应用除法算法得到，每一步的余数都可以表示为a和b的线性组合。例如，在欧几里得算法的最后一步，余数为0，此时最后的非零余数就是d。这表明d可以写成a和b的线性组合，因此存在整数x和y使得ax + by = d。
    ```cpp 
    int exgcd(int a, int b, int &x, int &y) {
    if (b == 0) {
        x = 1;
        y = 0;
        return a;
    }
    int d = exgcd(b, a % b, y, x);
    y -= (a / b) * x;
    return d;
    }
    ```

9. **连续递增的值填充**
    iota 是 C++ STL 中的一个算法，定义在 <numeric> 头文件中。它的作用是用连续递增的值填充一个范围。
    功能上：   
    ```cpp
    iota(b.begin(), b.end(), 0);

    for(int i = 0; i < b.size(); i++) {
        b[i] = i;
    }
    ```
```cpp
#include<bits/stdc++.h>
using namespace std;

bool com(const pair<int,int> &a, const pair<int,int> &b) {
    return a.first < b.first;
}

bool comp(const pair<int,int> &a, const pair<int,int> &b) {
    return a.second < b.second;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int T;
    cin >> T;
    while(T--) {
        int n, k;
        cin >> n >> k;
         
        vector<pair<int,int>> a(n+1), b(n+1);
        a[0]=b[0]={-1,-1};
        for(int i = 1; i <= n; i++) {
            int tmp;
            cin >> tmp;
            a[i] = {tmp, i};
        }
        
        if(k < n ) {
            cout << "-1\n";
            continue;
        } 
        auto sum = 1ll * n * (n + 1ll) / 2;
        
        sort(a.begin(), a.end(), com);
        for(int i = 1; i <= n; i++) {
            b[i] = {i, a[i].second};
        } 
        int x = n;
        while(sum > k && x > 1){
            if(sum - k <= x - 1){
                int t = sum - k;
                sum = k;
                swap(b[1], b[t + 1]);
            }
            int t = x + x - 3;
            if(sum - t >= k){
                sum -= t;
                swap(b[x], b[x - 1]);
                x -= 1;
            }
            x -= 1;
        }
        if(sum != k){
            b[1].first = 3;
            b[2].first = 4;
            b[3].first = 1;
            b[4].first = 2;
            sum = k;
        }
          
        sort(b.begin(), b.end(), comp);
        for(int i = 1; i <= n; i++) {
            cout << b[i].first << ' ';
        }
        cout<<endl;
    }
    return 0;
}
```

17. Brian Kernighan 算法
    可以在一定程度上进一步提升计算速度。Brian Kernighan 算法的原理是：对于任意整数 x，令 x=x & (x−1)，该运算将 x 的二进制表示的最后一个 1 变成 0。因此，对 x 重复该操作，直到 x 变成 0，则操作次数即为 x 的「一比特数」。

57. 数据结构常见搭配
- 图的邻接表：`vector<vector<int>> g(n + 1);`
- 带权图：`vector<vector<pair<int, int>>> g(n + 1);`
- 计数：`map<int, int>` 或 `unordered_map<int, int>`
- 判重：`set<int>` 或 `unordered_set<int>`
- 单调队列：`deque<int>`
- 动态维护最小值/最大值：`priority_queue`

58. 比赛里怎么选
- 需要随机访问，优先 `vector`
- 需要先进先出，选 `queue`
- 需要后进先出，选 `stack`
- 需要双端操作，选 `deque`
- 需要自动排序且去重，选 `set`
- 需要键值映射，选 `map`
- 需要更快查询且不关心顺序，选 `unordered_map` / `unordered_set`
- 需要一直取最小值或最大值，选 `priority_queue`

59. 容易写错的点
- `queue` 没有 `top()`，只有 `front()`
- `stack` 没有 `front()`，只有 `top()`
- `priority_queue` 默认是大根堆
- `map[key]` 如果 key 不存在，会自动创建
- `set` / `map` 的 `find` 返回的是迭代器，不是下标
- `vector::erase()` 删除中间元素代价较高，不适合频繁删除中间元素
